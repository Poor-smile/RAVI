# ADR: جداسازی و بازیابی renderer مرمید

- وضعیت: پذیرفته‌شده
- تاریخ: ۱۴۰۵/۰۵/۱۲
- دامنه: نسخهٔ فعلی Tauri؛ بدون تغییر ظاهر محصول یا فرمت سند

## زمینه

اجرای `mermaid.render` در WebView اصلی با timeout مبتنی بر `Promise.race` قابل متوقف‌کردن نبود. یک نمودار معیوب می‌توانست صف سری را نگه دارد، SVGهای تزریق‌شده DOM بزرگی بسازند و دو cache مستقل نیز سقف حافظهٔ واقعی نداشتند.

## تصمیم

در Tauri تنها یک `WebviewWindow` مخفی به‌عنوان renderer ساخته می‌شود. ارتباط آن با UI اصلی job-based است و شامل شناسهٔ سند، بلوک، نسل، تم و اولویت می‌شود. scheduler مستقل فقط یک job را هم‌زمان اجرا می‌کند، اولویت `interactive > visible > prefetch` دارد، درخواست یکسان را ادغام می‌کند و برای هر بلوک سیاست latest-wins را اعمال می‌کند.

در timeout پنج‌ثانیه‌ای یا crash، خود WebView renderer بسته می‌شود؛ بنابراین اجرای JavaScript جاری واقعاً پایان می‌یابد. job بعدی یک context تازه می‌سازد و بدون reload برنامه ادامه می‌دهد. مسیر وب و Electron یک transport محلی سازگار برای توسعه و آزمون دارد، اما تضمین «توقف واقعی پردازش» مختص transport ایزولهٔ Tauri است.

خروجی به شکل `SVG string → sanitize → Blob URL → <img>` نمایش داده می‌شود. source پاک‌سازی‌شده برای export و cache نگه داشته می‌شود، اما SVG در DOM اصلی تزریق نمی‌شود. یک cache مشترک LRU با سقف ۲۸ MiB، اندازهٔ UTF-8 واقعی، pin برای آیتم فعال و آمار توسعه جای دو cache قبلی را می‌گیرد.

نمودارهای خارج viewport پس از چهار ثانیه unmount می‌شوند و placeholder ارتفاع را حفظ می‌کند. prefetch فقط در idle انجام می‌شود. pan/zoom با `requestAnimationFrame` مستقیماً transform عنصر را تغییر می‌دهد و state React تنها با نرخ محدود همگام می‌شود.

## پیامدها

- نمودار سنگین دیگر thread رابط اصلی Tauri را اشغال نمی‌کند.
- timeout با destroy کردن context قابل بازیابی است و stale result نمایش داده نمی‌شود.
- تعداد nodeهای نمودار در DOM اصلی مستقل از پیچیدگی SVG است.
- هزینهٔ راه‌اندازی نخستین renderer وجود دارد و در mark جداگانه ثبت می‌شود.
- تعامل داخلی عناصر SVG عمداً وجود ندارد؛ تعامل ظرف نمودار، zoom و export حفظ می‌شود.
- CSP فقط `blob:` را برای نمایش تصویر محلی مجاز می‌کند و sanitizer بدون تضعیف باقی می‌ماند.

## گزینه‌های ردشده

- `Promise.race` در همان WebView: کار JavaScript را متوقف نمی‌کند.
- چند worker/renderer موازی: مصرف حافظه و ترتیب نتایج را پیچیده می‌کند.
- نگه‌داشتن SVG inline: DOM سنگین و هزینهٔ layout را به UI اصلی برمی‌گرداند.
- cache بر اساس تعداد entry: تفاوت شدید اندازهٔ SVGها را نادیده می‌گیرد.
