- لایت: worktree `RAVI-light`، شاخهٔ `Ravi-light`؛ خروجی آزموده‌شدهٔ `light-dist`.
- پشتیبان کامل نسخهٔ پیشین در میزبان، خارج از webroot:
  `/home3/hpoorsma/tmp/raviweb-before-2.4.6-20260913.tar.gz`.
- فایل‌های assets و لایت ابتدا منتقل و صفحهٔ `index-staged-2.4.6.html` بررسی شد؛
  سپس `index.html`، `.htaccess` و `version.json` جایگزین شدند.
- پس از مشاهدهٔ مسدودشدن فونت کوچک KaTeX توسط CSP، `assetsInlineLimit: 0`
  اضافه شد؛ گیت لایت دوباره گذشت و بستهٔ اصلاحی منتشر شد. CSP تضعیف نشد.
- پس از تأیید، سه آرشیو بارگذاری و صفحهٔ staging به `/home3/hpoorsma/tmp` منتقل شدند.
- پنجرهٔ «دربارهٔ راوی» روی سایت عمومی نیز شمارهٔ 2.4.6 را نشان داد.
- هیچ دادهٔ مرورگر یا فایل شخصی کاربر برای استقرار پاک نشد.

## شواهد بررسی

- build وب، سقف chunkها، سه آزمون هدایت دستگاه/ترجیح کاربر/حریم خصوصی: موفق.
- `light:release:check`: تطبیق lock، ممیزی بدون آسیب‌پذیری، TypeScript، آزمون‌ها و build موفق.
- ۵۵۶ فایل نهایی/حفظ‌شدهٔ خروجی با دریافت HTTPS و SHA-256 مطابق نسخهٔ محلی‌اند؛
  گزارش `.artifacts/web-public-hashes.json`.
- ورودی‌های اصلی، manifest و worker پاسخ ۲۰۰ با hash صحیح دارند؛ HTML دارای
  `no-cache` و worker دارای `no-store` است. فایل JS گم‌شده پاسخ ۴۰۴ می‌گیرد.
- Chrome در سه اندازهٔ رایانه، موبایل و تبلت، بارگذاری و هدایت صحیح و بدون
  خطای JavaScript داشت: `.artifacts/web-live-smoke.log`.
- آزمون Chrome در context مستقل: ورود Markdown، ویرایش سلول، انتخاب کل متن با
  دوبار کلیک، عنوان منوی ردیف، بازگشایی پیش‌نویس پس از reload، و reload آفلاین
  با محتوای یکسان موفق بود: `.artifacts/web-live-functional.log`.
- این آزمون‌ها جای آزمون روی دستگاه واقعی iPhone/iPad/Android و نصب PWA را نمی‌گیرند.

## ساخت مجدد و بازگشت

پس از موفقیت گیت لایت، مسیر مطلق خروجی آن را در `RAAVI_LIGHT_DIST` قرار دهید و
`npm run build:web-static` را در worktree انتشار اجرا کنید. خروجی نهایی
`.deploy-raavi-web` و `raavi-web-cpanel.zip` است؛ scripts/package-web-static.mjs
scope لایت را بررسی می‌کند. اسکریپت هدایت تنها در خروجی وب تزریق می‌شود.

برای بازگشت، آرشیو قبلی را ابتدا خارج از webroot استخراج و دارایی‌هایش را برگردانید؛
سپس index و .htaccess پیشین را جایگزین کنید. داده‌های مرورگر را پاک نکنید.
برای لایت، build سازگار با schema فعلی ذخیره منتشر کنید و نسخهٔ worker را تغییر دهید؛
تب در حال ویرایش را به‌اجبار reload نکنید.
