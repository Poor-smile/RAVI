# اجرای دستورالعمل انتشار 2.4.5 — ۲۰۲۶/۰۹/۰۶

این گزارش اجرای انتشار است؛ به‌معنای فعال‌شدن نسخهٔ جدید در updater نیست.
پس از اعلام نبود گواهی Code Signing، کاربر درخواست کرد دستورالعمل انتشار ادامه
یابد. وضعیت unsigned ویندوز در README و CHANGELOG صریح شده است و هیچ ادعای امضای
Authenticode یا اجرای موفق نصب واقعی مطرح نمی‌شود.

## مراحل انجام‌شده

- نامزد نهایی Windows همان فایلِ آزمون‌شده با ۴۶۱ آزمون واحد و ۲۳۸ آزمون عملکردی
  موفق است. یک آزمون R10 ورودی اختصاصی در دسترس ندارد.
- محتوای README و CHANGELOG برای تغییرات و محدودیت‌های 2.4.5 تکمیل شد؛ نسخه و
  وابستگی‌های برنامه در این مرحله تغییر نکردند.
- مسیر FTPS هاست دانلود، `/public_html/raavi/stable/`، با ساختار نسخه‌های عمومی
  2.2.0 و 2.2.1 تطبیق داده شد. اتصال با TLS و کلید عمومی pinشدهٔ هاست برقرار شد.
- نصب‌کننده و فایل SHA-256 در پوشهٔ مستقل 2.4.5 آپلود شدند.
- نصب‌کننده از نشانی عمومی کامل دانلود شد: HTTP 200، اندازهٔ ۱۰۵٬۵۸۲٬۱۱۳ بایت،
  SHA-512 و امضای Ed25519 صحیح. درخواست Range نیز HTTP 206 و همان ۱۰۲۴ بایت نخست
  فایل را برگرداند.
- مانیفست عمومی فعلی 2.2.1 برای rollback ذخیره شد و تغییری نکرد.
- دسترسی GitHub برقرار است؛ شاخهٔ فعلی و `origin/main` پیش از انتشار روی همان
  commit قرار دارند. tag/Release نسخهٔ 2.4.5 هنوز ایجاد نشده است.
- فایل‌های منبع مرتبط برای commit شناسایی شدند؛ خروجی‌های موقت، cache، ابزارهای
  طراحی نامرتبط و اطلاعات اتصال از مجموعهٔ انتخاب‌شده کنار گذاشته شدند.

۲. سپس commit، tag و Release عمومی GitHub همراه نصب‌کننده و checksum ثبت شوند.

۴. بعد از دریافت و بررسی خروجی‌های macOS، مانیفست چندسکویی، متن نهایی Release و

نشده است. شواهد اجرا در `.artifacts/release-execution-2.4.5/` و متن Release آماده
در `artifacts/release-2.4.5/RELEASE_NOTES_FA.md` نگهداری می‌شوند. اطلاعات ورود در
فایل‌ها یا گزارش‌ها ذخیره نشده‌اند.
