# یکسان‌سازی وابستگی‌ها و رفع مشکل Mermaid

تاریخ: ۲۰۲۶/۰۹/۰۵ — نسخهٔ برنامه: `2.4.5` — محیط بررسی: Windows x64، Node `24.18.0`، npm `11.16.0`.

دامنهٔ این مرحله، وابستگی‌ها، Mermaid و ساخت پاک است. این نتیجه تأیید انتشار عمومی و جایگزین اجرای کامل ممیزی محصول نیست. تغییرات قبلی پوشهٔ کار حفظ شده‌اند؛ commit و انتشار انجام نشده است.

## وابستگی‌ها

`npm@11.16.0` مدیر بستهٔ مرجع و `package-lock.json` تنها قفل JavaScript شد. فایل‌های رقیب pnpm پس از نگه‌داشتن نسخهٔ قبلی در پوشهٔ شواهد حذف شدند؛ `src-tauri/Cargo.lock` برای Rust باقی است. نصب با مدیر بستهٔ دیگر یا npm با نسخهٔ متفاوت در `preinstall` رد می‌شود. پیش از هر `npm run build`، تطابق manifest و نسخه‌های نصب‌شده با قفل و نبود فایل‌های مدیر بستهٔ رقیب بررسی می‌شود. گردش انتشار macOS نیز نسخهٔ npm و کنترل قفل را اعمال می‌کند؛ اجرای خود آن گردش روی macOS در این مرحله انجام نشده است.

Electron و Playwright روی نسخه‌های نصب‌شده و آزمایش‌شدهٔ قبلی صریحاً pin شدند. وابستگی‌های غیرمستقیم آسیب‌پذیر نیز از محدوده‌های سازگار به‌روز شدند. برای `@esbuild-kit/core-utils`، نسخهٔ `esbuild@0.25.12` به‌صورت override محدود ثبت شد؛ تبدیل TypeScript همگام و ناهمگامِ خود این loader با اجرای خروجی آزمون شد. Drizzle در پوشهٔ آزمایشی توانست schema فعلی را بخواند. Downgrade اجباری Drizzle انجام نشد.

Vinext به نسخهٔ beta ارتقا یافته است. سازگاری آن با build، رابط Electron، خروجی Word/PDF و کنترل‌های محتوایی زیر بررسی شد؛ موفقیت این سناریوها به‌معنای اجرای تمام آزمون‌های محصول نیست.

## Mermaid

نسخهٔ جدید شامل اصلاح advisory رسمی [XY infinite-loop DoS](https://github.com/mermaid-js/mermaid/security/advisories/GHSA-2v8p-3f2j-5mp7) است. ورودی سالم و همان نمونهٔ سه‌خطیِ محور با ابتدا و انتهای برابر، در فرایند جدا با `--max-old-space-size=192` بررسی شدند. هر دو با کد صفر و بدون اتمام حافظه پایان یافتند. در بازآزمایی هدفمند، زمان کل حدود ۱٫۳۶ و ۱٫۲۶ ثانیه بود. این گزینه سقف old-space است، نه سقف کل حافظهٔ سیستم‌عامل.

آزمون رگرسیون برای بارگذاری سرد ماژول ۳۰ ثانیه و پس از آماده‌شدن کتابخانه برای پردازش ورودی ۸ ثانیه مهلت دارد. اجرای تشخیصی اولیه هم‌زمان با build، حتی برای کنترل سالم به مهلت بارگذاری برخورد کرد؛ شواهد آن حفظ شده و نتیجهٔ معتبر پس از تفکیک بارگذاری از پردازش ورودی ثبت شد.

در Electron، رندر به پنجرهٔ مخفی اختصاصی با session جدا، sandbox و preload محدود منتقل شد. این پنجره رابط سند و API فایل یا حساب‌ها را بارگذاری نمی‌کند؛ درخواست‌های شبکهٔ خارج از origin محلی، مجوزها و بازکردن پنجره ممنوع‌اند. ارسال نتیجه فقط از main frame همین پنجره پذیرفته می‌شود. فرایند اصلی نگهبان ۵ثانیه‌ای دارد؛ هنگام توقف، PID موتور نمودار با PID پنجرهٔ اصلی مقایسه و فقط فرایند مستقل موتور قطع می‌شود. درخواست بعدی موتور تازه می‌سازد.

آزمون واقعی، تفاوت PID، زنده‌ماندن حلقهٔ رویداد پنجرهٔ اصلی حین حلقهٔ همگامِ عمدی در موتور، پایان درخواست با timeout و موفقیت رندر بعدی پس از timeout و crash را تأیید کرد. همین آزمون روی فایل اجرایی بسته‌بندی‌شده نیز موفق شد. مسیر Tauri حفظ شده است؛ وب از کتابخانهٔ اصلاح‌شده استفاده می‌کند، اما رندر DOM آن همچنان در محیط رابط مرورگر اجرا می‌شود.

## نصب و ساخت پاک

نسخهٔ محلی Git در `D:/codex/raavi-clean-dependency-mermaid-20260905` ساخته شد و فایل‌های منبع جاری، شامل تغییرات ثبت‌نشدهٔ مرتبط، در آن قرار گرفتند. این پوشه در شروع `node_modules`، `dist` و cache ساخت پروژه نداشت؛ وابستگی‌ها با `npm ci` از قفل نصب شدند. پوشهٔ اصلی نیز با همین دستور دوباره نصب شد. cache دریافت بسته‌های npm می‌تواند استفاده شده باشد؛ خروجی build و پوشهٔ نصب قبلی کپی نشدند.

Vinext جدید دارایی‌ها را زیر `dist/client/_next/static/chunks` می‌نویسد. کنترل حجم برای همین مسیر اصلاح شد؛ سقف‌ها افزایش نیافتند. اندازه‌های نهایی: Markdown برابر ۳۱۹٫۹ از ۳۲۲ KiB، Mermaid Studio برابر ۱۴۹٫۹ از ۱۵۰ KiB، Cytoscape برابر ۴۲۴٫۴ از ۴۶۰ KiB.

در آزمون سند سنگین شامل ۲۶ نمودار، صفر Long Task بیش از ۱۰۰ میلی‌ثانیه روی رابط اصلی ثبت شد. بیشترین تأخیر حلقهٔ رویداد در دو اجرای روشن و تاریک، حدود ۱۳ و ۷۱ میلی‌ثانیه بود. این اندازه‌گیری مربوط به همین میزبان است و benchmark دستگاه حداقلی نیست.

شواهد در [dependency-mermaid-fix-2026-09-05](../.artifacts/dependency-mermaid-fix-2026-09-05) قرار دارند. سیزده فایل کلیدی منبع و قفل نیز میان پوشهٔ اصلی و پوشهٔ ساخت پاک با SHA-256 تطبیق دارند. package.json داخل asar توسط electron-builder نرمال‌سازی می‌شود و مقایسهٔ بایتی یکسان برای آن ادعا نشده است.

## حدود نتیجه و اجرای مجدد

این مرحله نمونهٔ مشخص توقف سرویس Mermaid، قابلیت قطع و بازیابی Electron و ناسازگاری وابستگی‌های ممیزی قبلی را پوشش می‌دهد. صفر بودن audit به‌معنای نبود همهٔ آسیب‌پذیری‌های ممکن نیست. اخطارهای deprecated بعضی ابزارهای غیرمستقیم، هشدار اندازهٔ chunk اصلی و هشدار سازگاری آیندهٔ config loader همچنان وجود دارند. بستهٔ Windows آزمایشی است؛ نصب‌کنندهٔ عمومی تازه، امضا، انتشار، نصب/ارتقا در VM و کل مجموعهٔ کارکردی این مرحله نیستند. سایر یافته‌های گزارش ممیزی قبلی باید جداگانه بسته شوند.

```powershell
npm ci
npm run test:mermaid-release
npm run test:unit
npm audit
```

منابع ارتقاهای امنیتی: [React Server Functions](https://github.com/react/react/security/advisories/GHSA-wx67-qw84-cm4g)، [Vite روی Windows](https://github.com/vitejs/vite/security/advisories/GHSA-fx2h-pf6j-xcff)، [esbuild dev server](https://github.com/evanw/esbuild/security/advisories/GHSA-67mh-4wv8-2f99). رفتار قطع فرایند با احتیاطِ اشتراک PID در [مستندات Electron](https://www.electronjs.org/docs/latest/api/web-contents#contentsforcefullycrashrenderer) تطبیق داده شد.
